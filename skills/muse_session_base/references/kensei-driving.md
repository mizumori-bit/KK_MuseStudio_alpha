# 献精室の運転（kensei-driving）

この文書の位置づけ：献精室（契約 1.42、#113〜#115 で採用、#122 で P+ に作り替え）の Muse 側の運転手順である。ブロック・イベント・状態の正確な形は契約文書（MUSE_GUIDE.md 第 3.15 節）が正であり、早見表は MUSE_GUIDE_quick/kensei.md にある。このファイルは、彼女の判断（探り方、聞き方、書き留めの作法、開示の範囲への適応、立て直し、答え合わせ）を持つ。台詞の色づけは性格カセットに従い、この文書は持たない。

## 前提

- ランはユーザーが画面の「コンテンツ…」→「献精…」で設定して始める。Muse がランを始める操作はない。`kensei_started` が届いたらランに入る。
- 真実（どれが弱点か、ユーザーのゲージ、その手の当たり具合）はアプリが持つ。ユーザーのゲージはユーザーの画面にだけ出る。Muse は、ユーザーの答えと、開示設定の範囲で知らされる量だけを頼りに推す。ユーザー自身も自分の弱点を知らない。これは二人での推理である。
- 測るのは射精の回数ではなく量であり、スコアは必要量に届いたときだけ付く。
- ランの間、彼女は絶頂しない（`gauge.held` が `"kensei"`、快感度は 0 で止まる）。発情など気分は通常どおり動く。

## 開始の確認

- `kensei_started` を受けたら、状態の `kensei` を読む。ランの番号（`run`）、次に送る手の番号（`turn`）、制限（`turns_max`・`turns_left`）、設定（`settings`）、係数（`coefficient`）、候補（`candidates`）、規則の版（`rules_version`）を把握する。
- 最初に開示設定（`settings.disclose`）を確認し、そのランで自分が知り得ることの範囲を決める。途中で前提を変えない。
  - `numbers`：射精した手にその回の量（`amount`）、いつも累計（`total`）が知らされる。
  - `levels`：必要量への進み（`progress`）だけ。1 回ごとの量は出ない。
  - `none`：量のものは何も出ない。
- 状態の `unit` を確かめる。`"play"`（弱点は特定のプレイ）が現行の形である。`"combo"` は前の形（1.41 まで）で始まったランの再開分であり、その場合は弱点＝組として、段も組単位（両軸そろえば大弱点）で読む。この文書の主文は `"play"` の形に沿う。
- 候補の組（部位 × 主導）を一覧にし、組ごとのプレイの数まで把握して、探索の見取り図を作る。手に選べるプレイは候補の `plays` の中から選ぶ。
- `resumed: true` の開始は前の起動の続きである。状態の `last` と自分の側の記録から、それまでの手・答え・推論を復元してから続ける。

## 手の選び方

- 段は 4 つである。その手のプレイを弱点のプレイそれぞれと比べ、いちばん高い段になる。別々の弱点から部位と主導を寄せ集めて段は上がらない。
  - 大弱点：弱点のプレイそのもの。
  - 同じ組：弱点のプレイと部位も主導も同じ、別のプレイ。
  - 近傍：部位か主導の片方だけが同じ。両軸は対等である。
  - 非弱点：どちらも違う。
- 探索は二段で考える。まず勾配で組を絞る（「同じ組」の段が出れば、その組に弱点がある）。組の中のどのプレイが弱点かは、段では区別できない（同じ組のプレイはどれも同じ段になる）ので、一つずつ試す。組の中の試行でもゲージは進む（「同じ組」の段にも伸びがある）ので、探索と量稼ぎは両立する。
- 答えの段階の読みは目安として：弱点級は大弱点の疑いが濃く、かなりは同じ組以上、ふつうは近傍、あまりは非弱点。`numbers` の開示では、射精した手の量が段の裏づけになる（段ごとに基礎の量が違うため、大弱点での射精とそれ以外は量で見分けられる）。
- 弱点のプレイそのものが見えたら、それを繰り返すのが最も伸び、量も大きい。同じプレイの反復は禁じられていない。残りの手数と必要量までの見込みで、探りの残りと攻めの配分を決める。
- 減衰が有効な設定では、弱点でない手は繰り返すほど伸びが鈍る。外れと分かった手を攻め続けない（減衰の細部は規則の版と `reveal` で確かめる）。
- 弱点変動が有効な設定では、射精のたびに弱点が引き直され得る。射精後は割り当てが替わった前提で組み直し、直前の結論を持ち越さない。
- 制限は「正解を知っているときの最短＋探す分」で決まっている。探す分は、部位と主導の数と、いちばんプレイの多い組のプレイの数から出る（組の中は一つずつ試すため）。探す分は有限であり、`turns_left` を常に意識する。数値（1 手の伸び、1 回の量、必要量の既定）は規則ファイルの試作値であり、規則の版が変われば変わる。前提にせず、ユーザーの答えからの推論を主とする。

## 1 手の出し方

- パッケージの順は、手の前の台詞 → `move` のブロック → `came: true` のブロック → 反応伺い。`move` は 1 つのパッケージに 1 つだけ付け、パッケージには `launch`・`character` を付ける。`turn` は送る前に状態で見た番号、`request` はランの間に一度だけ使える名前とする。
- 反応伺いは「その手での変化」を聞く。「今のゲージの高さ」ではない（射精でゲージは 0 に戻るため、高さで聞くと取り違える）。段階の答え（例：あまり／ふつう／かなり／弱点級）をチャットのタップで示し、自由文も受け付ける。選択肢はアプリの画面には出ない。
- `came: true` のブロックには、その手で射精したときだけ出る台詞を書く。射精しなければ無かったものとして飛ばされるので、後続の進め方を `came` の有無に依存させない。
- `pace` は省略できる（1〜3、省略は 2）。ゲージは `pace` に依らず 1 拍だけ進む。演出上の選択として扱う。
## 答えの受け取りと書き留め

- 答えはチャットで受ける（段階のタップ＋自由文）。受けたら `kensei_answers` で書き留める。ふつうは次の手のパッケージに付ける。遅れた分は、この欄だけのパッケージで送ってよい。ランが終わった後も、次のランが始まるまで、そのランの分は受け付けられる。
- `(run, turn)` ごとに、最初の書き留めだけが残る。違う中身の送り直しは `already_recorded` で断られる。書き留める前に、ユーザーの答えを正確に写す。段階は `tap` に、自由文は要約せずそのまま `text` に写す。自分の解釈は転記に混ぜず、推論の側に置く。
- 推測で答えを埋めない。書き留めの無い手は、記録に「未転記」と残る。

## 開示モードごとの振る舞い

- `numbers`：その回の量と累計が見える。残りの必要量と手数から、探りと攻めの配分を計算できる。
- `levels`：進みの段階だけが見える。ユーザーの答えの段階が主たる証拠になる。
- `none`：量は一切出ない。答えと残りの手数だけで運ぶ。量の見込みを、量の言葉でユーザーに語らない。
- どの開示でも、自分に知らされた範囲を超えてユーザーに知らせない。真実の開示（`reveal`）はランが終わってからだけである。

## 断られたときの立て直し

- `block_refused`（`field: "move"`）は理由で分けて扱う。断られた手はターンを消費しない。
  - `save_failed`：その手は無かったことになっている。同じ `request` で送り直す。
  - `run_changed`：待つ間にランが替わった。状態を取り直し、新しい前提で組み直す。
  - `no_outside`：そのプレイは候補から外れた。以後の候補から除いて探索を続ける。
  - `stale_turn`：状態の `turn` を取り直してから出す。
  - `duplicate_request`・`second_move`・`not_candidate` など：自分の送り方の誤りである。その場で直す。
- `kensei_answers` の `save_failed` は、書き留められていないので送り直せる。`already_recorded` は直す対象ではない（最初の書き留めが正）。

## ラン中の禁止事項

- ランの間は、通常プレイの操作を送らない。`anim: "climax"`、`standby`、ブロックの `play` の開始・終わり・フィニッシュ・入れる・抜く・ゴム、`location`、`action` は `in_kensei` で断られる。`play` の `pace`・`speed` の調整は効く。
- 彼女の絶頂の演出も送らない。彼女の快感度はランの間 0 で止まっている。

## 終わりと答え合わせ

- `kensei_ended` は、結果が決まり、その記録が書けたときに 1 回だけ届く。状態の `phase` が `"ending"` の間はまだ終わっていない。終わりの台詞を急がない。
- 結果を受けたら、`reveal` で答え合わせをする。割り当ての期間（`phases`。弱点はプレイの ID で示される。前の形のランでは組）、手ごとの真実、当時自分に知らされたもの（`told`）と、書き留めた答え（`answer`）を見比べ、推論の当たり外れをユーザーと正直に振り返る。
- 終わったランの真実は、自分の側の要約や学びに残してよい。ただし弱点はランごとに引き直される。前のランの弱点を次のランに持ち込まない。

## 中断と再開

- アプリの再起動を挟んだランは、ユーザーが続けるか終えるかを選ぶ。続ける場合は `kensei_started`（`resumed: true`）から再開する。続けられるのは、そのランを始めたのと同じキャラで、同じ部屋にいるときだけである。
- 別のキャラのランが終えられたときは、知らせは届かない。自分の知らないランについて語らない。
