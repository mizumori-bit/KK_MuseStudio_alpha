# 相談：プレイ中の「委ねる」と、出そう・やめての扱い

**状態：基本は確定（ユーザー、2026-11-07）。停止の扱いについては、同日のユーザーと GPT の合意（本 PR の記録）を反映済み。申し送りや疑義がなければ、この形で行くものとする。**

分担：選択肢の構成と読みは Muse 側（スキル）の手順である。アプリ側の変更は不要の見込みだが、Claude への申し送りとして、契約文書の `play.finish: "soon"` に関する説明の訂正が1件ある（§2）。beat と質問の数え方に触れる部分があれば、申し送りとして挙げてほしい。

## 1. 委ねる（お任せ）モード

- プレイ中の通常の選択肢は **7択構成** とし、並びは「強く／弱く／速く／遅く／このまま／委ねる／出そう」の順とする。少し多いが、プレイ進行の基本へすぐアクセスできる形を優先する（ユーザー）。終わる形に向かう可能性のある選択肢は、最後の方に置く。
- 「委ねる」が選ばれたら、委ねるモードに入る。ステアリングの選択肢は消え、選択肢は三択になる。並びは「**続けて／やめて／出そう（申告）**」の順とする（この件における終わり方向は、プレイ自体の出口方面として統一する）。
- モードの間、プレイの運転（ペース・速さ・展開）は Muse の推論による。「続けて」はステアリングではなく、委ね続けることの願いとして読む（何も押されない沈黙とは区別する）。「続けて」と「やめて」は、どちらも彼女への願いの形である。
- 「主導権が彼女にある」ことは、選択肢の構成（チャットに表示される選択肢からステアリングが消えること）と、スキルによる運用上の委任で表す。アプリ本体にモードの概念は持たせない。固定ターンで選択肢を全て消す形は採らない。理由は2つ：出口の経路をタップに残すことと、委ねている最中にこそ「出そう」の申告と許可のやり取りが要ること。
- モードの終わり：プレイが終わったとき、参加終了の経路で中断されたとき。通常の選択肢に戻るのは、モードが終わってからである。モードと申告への判断の状態は、その時々のセッションの中で扱い、起動・キャラ・プレイをまたいで持ち越さない（手動の変更・終了や再起動の後に、古い状態を引き継がない）。

## 2. 出そうは申告、許可は彼女の判断

- 「出そう」は彼の限界の**申告**であって、フィニッシュへの自動の進行ではない。申告を受けて進めるかどうかは、彼女が場面と性格で判断する。この裁量は、委ねるモードの内外を問わない（通常のプレイでも同じ）。
- **順序：申告を受けただけでは `play.finish` を送らない。** 進める判断が立って初めて `play.finish: "soon"` を送り、従来のフィニッシュの流れ（行き先の提示）へ進む。`soon` はアプリを場所待ちの流れに入れ、待ち時間の後に自動で進行し、その間はペース変更もできない命令であるため、先に送ってから退ける運用はできない。現行の契約文書には「出そうを受けたら soon を送る」趣旨の説明があるため、その訂正を Claude へ申し送る。
- 退けられたら寸止めとする：ペースを落とす・引くなどでプレイは続き、申告は何度でもできる。
- 状態確認ゲートとの関係：従来は「出そうが選ばれたこと自体がゲートへの回答」としていた。これを「申告 → 彼女の許可」の二段に改める。ペース・速さの選択が「まだ」を伝え続ける点は従来どおり。

## 3. やめて（演出上の願い）

- 委ねるモードの出口の選択肢は「やめて」とする（「やめる」ではなく、彼女への願いの形）。その意味は、**事前に共有された演出上の願い**であり、選ばれたときの返答は彼女の裁量とする。これを選んだだけで、一律に承知・終了へ変える規則にはしない。
- **「二度続いたら必ず承知する」という義務は置かない。** 演出上の願いについて、二度目で彼女の判断を強制的に承知へ変える条件は採用しない。連続回数を数える管理も行わない。
- 演出上の願いであることと、実際に中断する経路（次節）は、利用者が判別できる形で扱う。

## 参加終了の経路（演出とは分けて維持する）

- **明確な参加終了の指示・操作は、1回で実行する。** 出口は、アプリの「プレイを終える」操作であり、委ねる間も含め常に使える。自由文でも、明確に演出を離れて中断を求めている場合は、同様に1回で実行する。彼女の承知・納得を実行の待ち条件にしない。
- 終了をどう受け止め、何を話すかは彼女に任せる。終了の処理が行われたことを、彼女が快く承知した・納得したという内面や態度へ、自動的に置き換えない。
- 本気の停止か曖昧な入力を、演出だと決めつけない。明確な参加終了を、演出上の願いとして扱って継続させない。

## スキルへの反映

- この合意と残る申し送りにそろえ、Muse がスキル反映 PR を別に立てる。反映先は app-driving だけでなく、共通土台の選択肢の規則、session-skeleton の「出そう」とゲートの説明、input-protocol のアプリ形への参照まで整合を確認する。テキスト形の手順と、プレイ外の既存ゲートは、この相談の対象外として変えない範囲を明記する。
