# 気分ゲージ：閉じている間の扱い（意見まとめと決定）

持ち主が各位（GPT・Claude・Muse）に意見を求め、集まった意見を持ち主が検討した結果のまとめです。方針は決定済みで、実装は Claude への引き継ぎとします。

## 問題

プレイ外（アプリを閉じている間）も尿意と発情が時間で溜まる現行の設計では、ユーザーのプレイ間隔次第で「起動するたびに毎回どちらも最大近くから始まる」体験になり得ます。

現行の数値（Claude の確認）：閉じている間の加算は発情が1分あたり 0.004（4時間で +0.96）、尿意が1分あたり 0.0035（4時間で +0.84）、上限は4時間分。そのため4時間以上空けて起動すると、ほぼ毎回満タン近くから始まります。尿意を 0 で終えても、次回の挨拶時には「もれそう」の段階に入ります。実測でも、試運転7と8はいずれも発情 1.0・尿意 1.0 で始まりました。

## 集まった意見

- GPT：プレイ外でも会話や操作をしている間は溜まるようにし、アプリを閉じている間や長時間の放置中は、尿意・発情ともに時間だけでは増やさない。前回の値は引き継ぐ（前回の展開で高くなった値を持ち越すことには意味がある）。
- Muse：止める方向に賛成。ただし全面停止より、閉じている間の蓄積に天井を付ける形（閉時間の加算だけでは閾値に届かない上限）を推した。根拠は試運転7・8の実測と、挨拶が毎回同じ切迫した形になる体験上の問題。
- Claude：閉じている間は「溜める」のをやめ、「ふだんの状態に落ち着く」にする。尿意は起動時に低い値から（閉じている間にトイレに行っているのが自然）、発情はふだんの水準（例えば 0.2〜0.4）へ近づけ、ひとりで始める域（0.85）や「疼いている」域（0.7）には届かない上限を設ける。開いている間の溜まり方は現行のまま。

## 決定（持ち主）

**Claude 案を採用します。** 閉じている時間は「彼女がふだんの生活をしていた時間」と見なし、値は落ち着く方向に扱います。

- 尿意：起動時は低い値から（少しばらつかせてよい）。
- 発情：閉じている間にふだんの水準（0.2〜0.4 の帯）へ近づける。閾値（0.85／0.7）には届かない上限を設ける。
- アプリを開いている間の蓄積は現行のまま変えない。
- 「時間だけでは増やさない」という GPT の核、「前回の値に意味がある」という点も、この形（高いまま固定はせず、ふだんへ寄せる）で両立させる。

細部の扱いは実装側の判断に委ねます。

- 落ち着き先の正確な値と、近づけ方（即時に寄せるか、閉時間に応じて段階的に寄せるか）。
- 空いた時間に応じて、上限の内側でわずかに高めに始める調整を入れるかどうか（「何日も会わないと少し溜まる」演出を残すかどうか）。

## 実装の見込み（Claude の見積もり）

小さく済む見込みです。気分の読み込み（Mood.cs）で「閉じていた間」の扱いを変え、設定（data/moods.json）に落ち着き先と上限を足す形。契約の形（状態に出る値やイベント）は変わらない想定です。変わる場合は、その旨を実装 PR に明記してください。
